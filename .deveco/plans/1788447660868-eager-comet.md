## Goal

单词卡片从"只看释义+例句"升级为"全方位深度学习"，覆盖词形变化、同反义词、搭配、词根词缀、易混辨析，同时 UI 上用折叠面板渐进展示避免信息过载。

## Scope / Non-goals

**包含：**
- 数据库 words 表加 6 个 JSON 列：`forms`、`synonyms`、`antonyms`、`collocations`、`etymology`、`distinction`
- content/*.json 格式扩展
- sync-content 同步新字段
- API 返回/接收新字段
- 卡片背面用 **折叠面板（Collapse）** 渐进展示
- 列表模式下新增字段可选显示

**不包含：**
- 不新建独立表（6 个字段都是 1:1 跟 word 走，无需拆表）
- 不做"自动生成词根/同义词"功能（数据源还是 content JSON 人工/批量准备）

## Current State And Constraints

### 现有数据结构

words 表列：id, word, phonetic, meaning, example_en, example_cn, mastery_level, interval_days, next_review, review_count, last_review, origin, user_modified, word_list, created_at

### 当前卡片 UI

- **正面**：单词 + 音标 + 复习信息
- **背面**：释义 + 例句 + 下次复习信息
- 翻转后左滑/右滑标记认识/不认识

### 约束

- 新列为 JSON TEXT 类型（SQLite 无原生 JSON 列，但支持 json_extract）
- 迁移必须幂等，已有数据不受影响
- sync-content 只更新内容字段，不碰进度字段
- 新字段可为空字符串（`''`），前端根据是否有内容决定是否展示对应折叠面板
- content JSON 新字段为可选，旧格式 words 仍可正常同步

## Design

### 1. 数据库迁移 — 006_words_enrichment

### 2. Content JSON 格式扩展

新增字段均为可选。示例：

```json
{
  "word": "abandon",
  "phonetic": "/əˈbændən/",
  "meaning": "v. 放弃；遗弃",
  "example_en": "He abandoned his old car and bought a new one.",
  "example_cn": "他丢弃了旧车，买了一辆新的。",
  "forms": {
    "past": "abandoned",
    "past_participle": "abandoned",
    "present_participle": "abandoning",
    "noun": "abandonment"
  },
  "synonyms": ["desert", "forsake", "relinquish"],
  "antonyms": ["retain", "keep", "maintain"],
  "collocations": [
    { "phrase": "abandon hope", "meaning": "放弃希望" },
    { "phrase": "abandon ship", "meaning": "弃船" },
    { "phrase": "abandon a project", "meaning": "放弃项目" }
  ],
  "etymology": "a- (away) + bandon (control)，源自古法语，意为'交出控制权'",
  "distinction": [
    {
      "word": "desert",
      "diff": "desert 强调违背责任/义务的抛弃，如 desert the army"
    },
    {
      "word": "forsake",
      "diff": "forsake 偏情感层面的断绝，如 forsake old habits"
    }
  ]
}
```

**设计决策**：
- `forms` 为 object（词形变化类型固定，适合结构化展示）
- `synonyms` / `antonyms` 为 string 数组（简单列表）
- `collocations` 为 object 数组（短语+释义配对）
- `etymology` 为纯文本（词根解析无需结构化）
- `distinction` 为 object 数组（对比词+差异说明）
- 所有新字段可选，缺失时存空字符串

### 5. 前端 UI — 卡片背面折叠面板渐进展示

**核心思路**：翻转后不把所有信息堆一屏，用折叠面板（手风琴模式）分层，用户主动展开感兴趣的维度：

```
┌─────────────────────────────────┐
│  ✅  v. 放弃；遗弃              │  ← 释义（始终可见）
│                                 │
│  ┌──────────────────────────┐   │
│  │ 例句                     │   │  ← 例句区（始终展开）
│  │ He abandoned his old...  │   │
│  │ 他丢弃了旧车...          │   │
│  └──────────────────────────┘   │
│                                 │
│  ▶ 词形变化                    │  ← 折叠面板（点击展开）
│  ▶ 搭配                       │  ← 折叠面板
│  ▶ 易混辨析                    │  ← 折叠面板
│  ▶ 同义/反义                   │  ← 折叠面板
│                                 │
│  ── 词根: a-(away)+bandon ──    │  ← 词根词缀（底部一行，始终可见）
│  ← 滑不认识 · → 滑认识          │
└─────────────────────────────────┘

展开"词形变化"后：
│  ▼ 词形变化                    │
│    abandoned    (过去式)        │
│    abandoned    (过去分词)      │
│    abandoning   (现在分词)      │
│    abandonment  (名词)         │
│  ▶ 搭配                       │
│  ▶ 易混辨析                    │
│  ▶ 同义/反义                   │
```

**折叠面板规则**：
- 只显示有数据的面板（空字段不生成面板项）
- 面板顺序：词形变化 → 搭配 → 易混辨析 → 同义/反义
- 手风琴模式：同时只展开一个面板，展开另一个自动收起前一个
- 词根词缀单独一行在底部（文字短，不需要折叠）
- 使用 Element Plus 的 `el-collapse` + `el-collapse-item` 组件

**为什么折叠面板优于 Tab**：
- 卡片空间有限，Tab 需要水平排列标签，词多时挤压或换行
- 折叠面板垂直排列，天然适合窄卡片
- 展开即可见内容，不需要切换后"忘了上一个 Tab 看了什么"
- 更轻量的交互，符合"翻转后快速扫一眼"的使用场景

**列表模式**：
- 新增"词形"列（紧凑显示，如 `abandoned/abandoning/abandonment`）
- hover/点击行展开详细 enrichment 信息

## Risks And Compatibility

- **数据量**：6 个 JSON 列会让每行更大，但 SQLite 单文件库对此无压力（1946词 × 几KB/行 < 10MB）
- **空值兼容**：新列默认空字符串 `''`，前端 `JSON.parse('')` 会抛异常，需 try-catch
- **content 生成**：批量补充 1946 词的丰富字段工作量大，AI 生成可能有错误，需抽样审核
- **迁移顺序**：迁移 006 必须在 sync-content 更新之前执行，否则 insert 会缺列报错

## Rollback

- 迁移不可逆（SQLite 不支持 DROP COLUMN 在旧版本），但新列默认空字符串不影响现有功能
- 前端回退：git revert 即可，新列为空时 UI 不展示对应折叠面板
- sync-content 回退：git revert，旧 insert 语句不含新列，默认值填充空字符串
